# Постоянные refs элементов ViewPrint

## Контекст

`extractSnapshotData` переназначает `data-viewprint-id` всем DOM-элементам при каждом capture. Engine сначала получает ref через `eval`, а команда `click` повторно вызывает capture и может назначить этот ref другому элементу. В Threads это привело к клику по невидимому `title` вместо кнопки публикации.

## Цель

Сохранить `data-viewprint-id` существующего DOM-элемента между capture, чтобы ref, полученный перед действием, указывал на тот же элемент во время `click` или `fill`.

## Что изменится

1. `src/extractor.ts` — переиспользовать существующий ViewPrint id и выдавать новые ids только новым элементам.
2. `tests/browser.test.ts` — проверить действие по ref после вставки DOM-элемента перед целевым элементом.
3. `CONTEXT.md` — записать причину и решение.

## Критерии приёмки

- [x] Повторный capture не меняет ref существующего элемента.
- [x] Новый DOM-элемент получает новый уникальный ref.
- [x] `click` по ref после изменения DOM нажимает исходный элемент.
- [x] ViewPrint lint, тесты и build проходят.
- [x] Engine check, lint, тесты и build проходят.
