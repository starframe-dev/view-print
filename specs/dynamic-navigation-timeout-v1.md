# Навигация динамических страниц без ожидания полного load

## Контекст

ViewPrint использует стандартный `page.goto(url)` и ждёт событие `load`. Threads и другие динамические сайты могут держать загрузку ресурсов открытой дольше 30 секунд, хотя основной DOM уже доступен. Из-за этого capture завершается timeout до account detection.

## Цель

Считать навигацию готовой после `DOMContentLoaded`, чтобы ViewPrint мог работать с динамическими страницами Threads, не ожидая завершения всех фоновых ресурсов.

## Что изменится

1. `src/browser.ts` — передать `waitUntil: 'domcontentloaded'` во все навигации `page.goto`.
2. `tests/browser.test.ts` — добавить проверку, что capture использует DOMContentLoaded-навигацию.
3. `README.md` — описать поведение навигации и ограничение фоновых ресурсов.

## Детали реализации

1. Не менять существующий timeout Playwright.
2. Использовать `waitUntil: 'domcontentloaded'` для `capture` и `newTab`, где выполняется навигация.
3. Сохранить последующую работу capture и polling account detection для динамически появляющегося DOM.
4. Не отключать timeout полностью и не скрывать реальные ошибки навигации.

## Критерии приёмки

- [x] Threads capture не ждёт событие полного `load` после готовности DOM.
- [x] Навигация `newTab` использует тот же режим ожидания.
- [x] Существующие тесты, lint и build ViewPrint проходят.
- [x] Глобальный CLI переустановлен из обновлённого пакета.
- [x] Engine и pipelines Миры проходят после обновления ViewPrint.
